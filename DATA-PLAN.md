## Long-term data behavior
- **Refresh policy**: Balances/prices read live from chain RPCs on load and on Refresh; never stored as balances (only a per-address last-synced snapshot for deposit detection). Custody vault (encrypted seed only), GTQ fee setting, custodial users, derived addresses, ledger balances/entries, transactions and contacts persist in ctx.db.
- **Growth**: One custody_vault row; one custodial_users row per user created by the operator (account_index increments, never reused while later users exist); 12 user_addresses per user; ledger rows append per deposit/send/swap/transfer/fee. Legacy wallets/addresses tables from v1 remain but are no longer used by the UI.
- **Ordering**: Assets GTQ first, then native coins and USDT/USDC per network; transactions newest first.
- **Time semantics**: Transaction timestamps are creation instants, rendered viewer-local.

## Honesty boundary (custody/signing)
Custodial rework (2026-11-19, verbatim request: 'Una billetera custodial como NC Wallet o como los exchanges que dan direcciones a todos sus usuarios con una sola frase semilla encriptada'):
- ONE master BIP39 seed per operator. Generated (12 words) or imported (12/24 words, checksum-validated against the official BIP39 English wordlist, bitcoin/bips bip-0039/english.txt, downloaded verbatim at build time into server/src/wordlist.ts). Encrypted at rest in ctx.db (custody_vault) with scrypt(passphrase, random salt) + AES-256-GCM; plaintext never stored. getCustodyStatus never returns it; setupCustody returns it ONCE for backup; recoverSeed returns it only with the correct passphrase (AES-GCM auth failure = wrong passphrase error).
- Derivation (server/src/crypto.ts, Node/Bun built-in crypto + pure-BigInt secp256k1 and pure Keccak-256 — Bun's ECDH lacks secp256k1): BIP39 seed via PBKDF2-HMAC-SHA512; BIP32 HMAC-SHA512 for secp256k1, SLIP-0010 for ed25519. Paths: EVM m/44'/60'/account'/0/0 (same address on all 10 EVM networks), Solana m/44'/501'/account'/0', Tron m/44'/195'/account'/0/0. Verified at build time: Keccak-256 empty/abc match known vectors; the abandon…about test mnemonic derives EVM 0x9858EfFD232B4033E47d90003D41EC34EcaEda94 (known BIP44 vector) and Tron TUEZSdKsoDHQMeZwihtdoBiN46zxhGWYdH; encryption roundtrip + wrong-passphrase failure verified.
- Email registration/login + permanent binding (follow-up 2026-11-19): custodial_users.email (migration 0004, normalized lowercase, format-validated, uniqueness enforced in createUser; duplicate email is rejected pointing to login). Registration = createUser{name,email,passphrase}; login = findUserByEmail{email} returning the account bound to that email. The email is immutable — no action updates or deletes a user (the earlier deleteUser action was removed), the account_index is never reused, so the email ↔ derived-addresses binding is permanent, as in NC Wallet/exchanges.
- Multi-user: custodial_users (account_index), user_addresses (derived per network), ledger_balances + ledger_entries (internal off-chain ledger). Per-user live on-chain balances reuse the probed RPC reads. Deposits credit the ledger via syncUserDeposits (on-chain increase since last snapshot per address) or creditDeposit (operator manual). Internal transfers settle only on the ledger, instant, with the GTQ fee charged to the sender. Sends/swaps (recordUserTransaction) debit the user's ledger + GTQ fee.
- Starts with ZERO users; no seeded/demo users or balances.
- Transparency kept in UI (Custodia tab): the encrypted seed lives in this artifact's DB (not an HSM); lost passphrase + lost paper backup = unrecoverable; sends/swaps are prepared/recorded with a payment payload — the artifact does not broadcast signed on-chain withdrawals itself.
